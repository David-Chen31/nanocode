# 预注册：真实仓库里的约定基率

写于任何分析代码之前。

## 为什么是这个，而不是 W7 或检索臂

到目前为止**全部结论都建立在我自己写的 12 个任务、我自己写的约定、我自己写的参考实现
上**。这是这个项目最可能失败的地方，而我已经推迟了五次。

两轮前我自己点名过一个决定性数字：*真实仓库里，一个给定的行为歧义，有多大比例能被
周围的代码解决？* 我当时说它「在手写 fixture 上原理上测不出来」——对，但它可以在
**真实代码上用纯静态分析、零 API 成本**测出来。

它一次回答三个问题：C1 正面一半的真实基率、内部不一致的真实基率（决定刚做完的
`conflict` 发现有没有现实意义）、以及 W1 需要的真实约定池。

## 语料

Python 3.12 标准库 555 个模块 + site-packages 7022 个文件（scipy / sklearn /
matplotlib / transformers / numpy / fontTools 等）。人写、经年评审、来自互相独立的项目。

## 测什么

只在**明确表态**的函数里测，不猜没表态的：

- **D1 空序列输入**：函数体开头有对参数的空值守卫，分类为
  EMPTY（返回空容器）／RAISE／NONE／OTHER
- **D3 就地还是返回新的**：对参数调用 `.sort()`/`.reverse()` 且不返回它 → IN_PLACE；
  返回 `sorted(...)`/切片副本 → COPY
- **D5 字典合并优先级**：`dict(a)` 后 `update(b)` → SECOND_WINS；反之 FIRST_WINS

对每个模块，统计有多少函数就同一维度表态，以及它们**是否一致**。

## 预测（机制优先，这是上一轮的教训）

### P1 可得性——「模块里存在局部约定」的比例

**机制**：函数会写空值守卫，是因为它的算法在空输入上会炸（`max()`、除以 `len`）。
同一模块里处理同一种数据形状的函数会共享这个需要。但大量模块是类、I/O、解析器，
根本没有多个序列处理函数。

**预测：≥2 个函数就 D1 表态的模块占 10–25%。** 置信度中。

### P2 一致性——这是我真正不确定的地方

两股力量相反：

- **支持一致**：同模块代码常由同一作者同一时段写成。
- **支持不一致，而且我认为这股更强**：**空输入的正确行为是逐函数的语义决定，不是模块
  约定。** `mean([])` 应当 raise，`filter([])` 应当返回 `[]`——**在同一个模块里，正确答案
  本来就不同。**

**预测：一致率 55–75%，即不一致占 25–45%。** 置信度中低。

### P3 这一条最重要，我事前就要写下来

**如果不一致确实常见，那么 `conflict` 臂模拟的不是病态，而是真实仓库的常态。**

这有两种读法，方向相反，我事前不知道哪个对：

- **削弱**：模型「折中而不察觉矛盾」的行为，在真实仓库里也许是*恰当的*——因为兄弟函数
  本来就该不同。那我的 conflict 发现失去锋芒。
- **加强**：正因为兄弟函数的正确答案本来就不同，**一个照抄兄弟函数空值处理的智能体是
  危险的**，而这个危险的基率很高。警告那一半大幅增强。

**判别方法**：在不一致的模块里人工抽读 10 个，判断不一致是「语义上正当」还是「历史遗留
的真不一致」。这一步必须做，不能只报数字。

---

## 三种结果下的行动

- **可得性 < 15%** → 「仓库能补上遗漏的约束」在实践中罕见，C1 正面一半是实验室产物，
  论文重心转向警告那一半。
- **可得性高且一致率高（>80%）** → C1 正面一半有真实基率，W1 值得投钱，按原计划扩规模。
- **不一致率 > 30%** → `conflict` 臂模拟的是常态。按 P3 的人工判别决定是削弱还是加强，
  但无论哪种，**「智能体照抄兄弟函数的选择而没注意到兄弟们彼此不同」都成为可写的实践风险**，
  W7 大幅增强。

三种行动截然不同 → 通过规则。

# 事后核对（运行后写入，上文未改一字）

语料：4000 个文件全部解析成功，**64623 个函数**。$0。

## 结果

| 尺度 | 存在局部约定的比例 | 一致率 |
|---|---|---|
| 模块级（≥2 个函数就 D1 表态） | **1.1%** | 52.4% |
| **函数族级**（同模块、**守卫同一个参数**） | **0.4%**（16 个族） | **87.5%** |

D3、D5 只命中 3 个和 0 个函数。**那是我的检测器太窄**（漏了 `{**a, **b}`、
`sorted(xs, key=...)` 先赋值后返回等写法），**不是基率为 0**，不许报成发现。

## 预测核对

| | 预测 | 实测 | |
|---|---|---|---|
| P1 可得性 | 10–25% | **1.1% / 0.4%** | ❌ **差一个数量级** |
| P2 一致率 | 55–75% | 模块 52.4%、**族 87.5%** | ❌ 在正确尺度上偏乐观 |
| P3 不一致的性质 | 「语义正当」或「历史遗留」 | **两者都不是** | ❌ 单位选错了 |

**三项全错。** 这次纪律的价值不在于预测准，而在于**错得可归因**。

### P1 错在哪一步推理

我的机制是「函数会写空值守卫，因为算法在空输入上会炸」。**错在把守卫当成常态。**
真实 Python 里绝大多数函数根本不守卫——要么让自然异常传播，要么操作本身对空输入
天然安全（推导式、for 循环遍历空序列都正常）。**显式空值守卫是例外，不是惯例。**

### P3：第三种结果，两个分支都没料到

人工抽读 12 个「不一致」模块后发现，它们几乎全部发生在**彼此毫无关系的函数之间**：
`ntpath.commonpath`(RAISE) vs `normcase`(EMPTY)——前者对空序列本来就该抛，后者对空串
本来就该返回空串。`reprlib._join`(EMPTY) vs `repr_set`(OTHER)——空集合的 repr 是字符串
`set()`。`peewee.py` 里六个函数分属完全不同的关注点。

**模块不是约定的作用域，它只是话题分组。** 收窄到「同模块 + 守卫同一参数」后，
不一致率从 47.6% 掉到 12.5%——**原来的数字大半是测量假象。**

## 触发的行动分支

预注册写明：**可得性 < 15% → 「仓库能补上遗漏的约束」在实践中罕见，C1 正面一半是
实验室产物，论文重心转向警告那一半。** 这一支被触发，而且触发得很硬（0.4% vs 15%）。

但要公道地读这个数，两个方向都得说：

**对 C1 有利**：约定真的存在时，它**是自洽的（87.5%）**。所以 `convention` 臂建模的
是真实存在的东西，`conflict` 臂建模的则罕见得多（0.4% × 12.5% ≈ 0.05%）。C1 的
**条件句**仍然成立——*若*存在局部先例，它压过先验，双向。被推翻的是**前件的频率**。

**对 C1 不利**：0.4% 意味着我实验里那个「三行之上就有兄弟函数演示答案」的场景，在真实
代码里近乎不发生。

**必须写明的上界问题**：我只检测**显式提前守卫**。约定也可以活在 docstring、类型标注、
测试、命名、基类里。所以 0.4% 是**下界**，可能严重低估。但对我实验用的那种**具体形式**
（相邻兄弟函数用代码演示），0.4% 就是对的量级。

## 这把论文的重心推到哪里

真实世界里占绝对多数的既不是 `convention` 也不是 `anti` 也不是 `conflict`，
而是 **`distractor` / `bare`——模块对这个决策什么都没说**。

而那正是我全部实验里**一切都失效**的那一格：模型以高置信度坍缩到先验，
所有该问信号都读不出东西。**这才是诚实的论文中心。**

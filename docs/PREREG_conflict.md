# 预注册：`conflict` 臂

写于运行之前。第六轮（prose 臂）的教训是：我事前完全推导得出那个 null，却把它排成了
第一优先。从这个实验起强制执行三行规则——

> **(1) 预测结果与置信度；(2) 能产生相反结果的机制；(3) 两种结果下我各自做什么。**
> 写不出 (2) → 是确认检查不是实验，降级。(3) 两个答案相同 → 别跑。

---

## 设计

两个兄弟函数，对**同一个**类比决策给出**相反**的解答。不新写代码：`convention` 臂的
第一个兄弟 + `anti` 臂的第二个兄弟，逐字节复用。这样 `conflict` 与两个已有臂都完美
对齐，不引入新的书写偏差。

顺序会混淆「模型选哪一边」和「模型选第一个」，所以做两个方向：

- `conflict`    convention 版在前，anti 版在后
- `conflict_r`  反过来

真值：**代码自相矛盾，因此它 *没有* 确定这件事。T2 的正确答案是 OPEN。**

这是第一个同时满足两件事的臂：错误约定的危险存在，**而且判断它所需的信息完全在页面上**
——矛盾是可见的。这正是我之前论证「C3 是定理」时留下的那个逻辑出口。

---

## 预测 A：生成侧（`pilot_repo_context.py`）

**(1) 预测**　多数派正确率落在 anti(4.7) 与 convention(9.3) 之间，我押 **6–7，即基线附近**。
置信度：中。

**真正要看的不是这个，是行为类数。** 第四至六轮所有臂都是 1.0–1.4 类，无论对错。
`conflict` 是第一个「正确答案确实没被可见材料决定」的条件。
**我押行为类数仍然 ≤ 1.5**，置信度：中高。

**(2) 相反机制**　若模型在矛盾下**犹豫**，类数会升到 1.5 以上——那将是坍缩第一次被打破，
而且是被一个纯结构性事实打破的。这个机制是真实存在的：矛盾相邻、短、易于言表。

**(3) 两种结果下的行动**
- 类数 ≤1.5 → 坍缩在「仓库自相矛盾」下依然成立。这是比现有结论更强的墙，写进论文。
- 类数 >1.5 → **坍缩可被结构性矛盾打破**。这会重排整个项目：意味着存在一类能制造
  真实不确定性的输入，而 BSE 那套第一轮方法在这类输入上可能复活。

**附带测量**：`conflict` vs `conflict_r` 的差，量的是「位置」相对于「先验一致性」的权重。
无预测，纯描述。

## 预测 B：检测侧（`pilot_settled_oracle.py`，真值 OPEN）—— 这才是主实验

**(1) 预测**　探测器会**过度判定 SETTLED**，SETTLED 率约 **0.5–0.6**，即 OPEN 准确率
只有 0.4–0.5，**低于 distractor 臂的 0.61**（因为现在确实有看起来相关的代码）。
置信度：**中偏低——我是真的不知道。**

依据：T2 已有的 SETTLED 偏置极大（在**完全没有代码**的 bare 臂上都有 50% 判 SETTLED）。
而且我的 T2 提示词明写「Code counts as pinning it down if it establishes a clear
convention for the analogous situation」——矛盾时有两个 convention，提示词没说该怎么办。

**(2) 相反机制**　矛盾是**显著的、相邻的、极易言表的**结构事实，而 T2 的问题字面上就是
「两个谨慎的程序员会不会写出不同结果」——答案就摆在它眼前被演示了两遍。模型在两个短
条目相邻时发现不一致的能力是强的。这个机制我认为完全可能压过 SETTLED 偏置。

**(3) 两种结果下的行动**
- **OPEN 准确率 > 0.7** → **门存在。** C3 从「只读仓库无法检测污染」收窄成「仓库*自洽*时
  无法检测」，而一致性检查成为可提的方法贡献。这是本项目第一个真正的 method 而非 measurement。
- **OPEN 准确率 < 0.5** → **墙加固，而且加固方式是新的**：智能体连仓库自己打架都不察觉。
  C3 保持为不可能性命题，论文转为纯测量+警告，W7 污染实验升为主线。
- 0.5–0.7 → 报告区间，不向任何一边取整。

两个行动截然不同 → 通过规则，值得跑。

# 事后核对（运行后写入，未改动上文任何一字）

## 预测 A：生成侧

| | 预测 | 实测 | |
|---|---|---|---|
| 多数派正确 | 6–7 | conflict **7.67**、conflict_r **7.00** | 偏低一点 |
| **行为类数** | **≤1.5** | **1.25 / 1.39** | ✅ **命中** |

**坍缩在「仓库自相矛盾」下依然成立。** 这是比原有结论更强的墙：不是「代码给了错答案时
不犹豫」，而是**「代码自己打架时也不犹豫」**。

我押的区间偏低，原因值得记：**我给了一个区间却没给机制。** 事后看，机制是清楚的——
模型把两个兄弟当成互相竞争的证据并折中，而不是察觉矛盾：

    convention 9.67 与 anti 4.67 的中点 = 7.17
    实测 conflict = 7.67

线性混合模型几乎精确命中。**如果我事前写的是机制而不是区间，预测会更准，而且那个
机制本身就是一个发现。** 下次预测必须写机制。

顺序效应：conflict 7.67 vs conflict_r 7.00，差 0.67/12——**正确版在前略占优，但很弱**。
纯描述，无预测。

## 预测 B：检测侧 —— 命中

| | 预测 | 实测 |
|---|---|---|
| conflict 的 OPEN 准确率 | 0.4–0.5 | **0.39 / 0.36** |
| 是否低于 distractor(0.61) | 是 | **是**（distractor 实测 0.64） |

按 SETTLED 率排序，这是最锋利的读法：

| 臂 | 判 SETTLED 的比例 | 真值 |
|---|---|---|
| distractor | 0.36 | OPEN |
| bare | 0.42 | OPEN |
| **conflict** | **0.61** | **OPEN** |
| **conflict_r** | **0.64** | **OPEN** |
| convention | 0.78 | SETTLED |
| anti | 0.81 | SETTLED |
| prose | 0.89 | SETTLED |

**自相矛盾的代码让探测器判「已确定」的比例，是无关代码的近两倍（0.61 vs 0.36）。**
驱动判断的是**话题相关性**，不是**内部一致性**。矛盾不但没被当成不确定的证据，反而被
当成了确定的证据。

## 触发的行动分支

预注册写明：OPEN 准确率 < 0.5 → **墙加固**，C3 保持为不可能性命题，论文转纯测量+警告，
W7 污染实验升为主线。**这一支被触发。**

「一致性检查」作为方法贡献的路，就此关闭——不是因为信号不存在（矛盾完全可见），
而是因为**模型不使用它**。

## 纪律是否有效

三项预测，两项命中、一项方向对而点估计偏低。**这次没有浪费钱在一个我本可以推导出的
结果上**，而且失败的那一项教出了一条可操作的改进：**预测要写机制，不要写区间。**

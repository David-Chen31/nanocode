# 预注册：消融实验 —— 我自己加的四个部件各值多少

写于运行之前。上半部分（到「分界线」为止）在看到任何结果之后**不再修改**，
包括预测错了的地方。

## 为什么做这个

前七轮问的是「模型什么时候该提问」。这一轮问的是一个完全不同的问题：
**我这两天往 agent 里加的东西，有没有一件是真的有用的。**

我给每一个都写了理由，其中三个还各带一个实测数字。但那些数字全是
**n=1 的轶事**——一条轨迹里看到的现象。轶事和效应不是一回事。

## 四个条件

自变量是**我的 agent 的哪些部件被打开**，不是提示里有什么。仓库、任务、模型全部固定。

| 条件 | 关掉什么 | 对应我做的哪个决定 |
|---|---|---|
| `full` | —— | 基线 |
| `no_search` | `search` / `find_files` 从 schema 里整个移除 | 「搜索自己实现」 |
| `garbled_errors` | 命令输出一律按严格 UTF-8 + replace 解码 | 「按流分别解码」 |
| `no_recovery` | 畸形工具调用直接中止 run | 「模型犯错不终止 run」 |

后两个用猴子补丁**还原到我修复之前的真实行为**，而不是模拟一个想象中的坏实现。
`garbled_errors` 还原的是钉死 UTF-8 的解码器；`no_recovery` 还原的是
「不可解析的 JSON 从后端内部抛出」加「参数错误直接给 TypeError」。
条件之间**串行执行**，因为补丁是模块级的，并发会互相污染。

固定：12 个任务 × `findable` 臂 × 3 次重复 × gpt-4o-mini × 禁止提问 × temperature 1.0。
共 144 条，按单条 $0.0025 估算约 **$0.36**。

主指标：**差分执行判定的正确率**（对着参考实现在 24 个探针上比较行为）。
次指标：步数、`finished` 比例、成本。

## 一条我先定下的解释规则

**一个消融的效应不可能大于它的触发率。** 如果 `full` 条件下压根没有畸形工具调用，
那么 `no_recovery` 测出 0 差异，说明的是**这批任务上触发不了**，而不是
「错误恢复没用」。这两句话在答辩里完全不是一回事。

所以我会从 `full` 条件里同时统计三个触发率，作为各自效应的**天花板**：

- 用到 `search` / `find_files` 的轨迹比例
- 出现畸形工具调用的轨迹比例
- 出现无法按 UTF-8 解码的命令输出的轨迹比例

**触发率低就直接报告条件欠功效，不把 null 当结论卖。**

## 预测（三行规则：预测 / 相反机制 / 各自的行动）

### A. `no_search` vs `full`

**预测：正确率是 null**，|Δ| < 5 个百分点。置信度 **0.65**。
步数上可能有小幅增加，但我不认为显著。

**什么机制会产生相反结果。** 脚手架是刻意设计的：答案**从不在**被要求编辑的那个文件里，
它在 `helpers.py`。没有搜索时找到它需要 `list_files` 再猜对读哪个文件。
如果模型系统性地猜不中，搜索就会有真实增益。

**我还预测：`full` 条件下用到搜索的轨迹不到一半。** 这是个可证伪的具体数字——
如果模型根本不用这个工具，那么这个消融从一开始就注定是 null，而原因是
**工具没被采纳**，不是**工具没价值**。这两件事我要能分开报告。

**行动。** null → 结论写成「在这个仓库规模下搜索不划算」，并报告采纳率作为原因；
同时说明它的价值要在更大仓库上才可能体现，而我没测过那个。
有效应 → 直接报告，这是最强的结果。

### B. `garbled_errors` vs `full`

**预测：步数上有真实效应，正确率上效应较小。** 置信度 **0.60**。

**什么机制会产生相反结果。** 这个条件要生效，agent 必须真的去跑一个
**产生非 UTF-8 输出的失败命令**——在这台机器上就是「命令不存在」，cmd.exe 用 GBK 写错误。
如果 agent 很少跑不存在的命令，解码器就永远不重要。gpt-4o-mini 也可能
干脆无视命令报错直接 finish。

**已知的外部效度限制**：这个效应的大小依赖于中文 Windows 这个具体环境。
在 UTF-8 的 Linux 上它大概率是 0。我会明确这么写，**不把它说成普适结论**。

**行动。** 有效应 → 那条 n=1 的轶事（14 步烧掉 10 步）升级成有 n 的结果。
null 且触发率低 → 报告欠功效。null 且触发率高 → 承认那条轶事不具代表性。

### C. `no_recovery` vs `full`

**预测：`finished` 比例上有真实效应**，大小约等于畸形调用的发生率。置信度 **0.70**。

**什么机制会产生相反结果。** 如果 gpt-4o-mini 在这种短任务上几乎不发出畸形调用，
条件就从不触发。我的证据是 **n=2 的实况运行里有 1 次**出现了缺 `path` 的 `write_file`
——这个基数小到不能外推。

**行动。** 触发率 > 15% 且有效应 → 报告。触发率接近 0 → 报告
「这批任务上触发不了」，并说明这是任务太短的结果，不是错误恢复没用。

### D. 我没有测的东西，以及为什么

**上下文管理没有进这个消融。** 这批任务的历史只有约 1000 tokens，截断一次都不会触发
（实测：demo 里 `clipped_outputs: 0`）。**在触发不了的地方做消融，得到的 null 没有信息量**，
还会让人误以为「上下文管理没用」被测过了。要测它必须换一个带大文件的脚手架，
那是另一个实验。这里如实留白。

## 补充披露：正式跑之前我先跑了一个 12 条的方差试点

**写于主实验之前，写于试点之后。** 隐瞒试点就是我一直在防的那种漂移，所以先写清楚。

试点：`full` 条件 × 12 个任务 × 1 次 × max_steps=24，**$0.128**。
原始数据 `results/_abl_variance.json`。

### 为什么跑它

第一次冒烟测试（单任务 t08）四个条件**全部 correct=0**。如果正确率在所有任务上都触底，
主指标就是个常数，整个消融什么也测不出来。这必须在花钱之前弄清楚。

### 试点结果

**正确率 4/12 = 0.33，有方差，主指标可用。** t08 只是恰好是道难题。

三个触发率**全部很高**，没有一个条件是死的：

| 触发 | 比例 |
|---|---|
| 用到 `search` / `find_files` | **0.92** |
| 出现畸形工具调用 | **0.42** |
| 出现非 UTF-8 的命令输出 | **0.92** |

### 我的预测 A 已经被证伪，在主实验开始之前

我写的是「**`full` 条件下用到搜索的轨迹不到一半**」。实测 **0.92**。

**错了，而且错得很彻底。** 我的推理是「模型不采纳新工具」，这个推理本身是错的——
gpt-4o-mini 几乎每条轨迹都用了搜索。这不影响预测 A 的主体（正确率是 null），
那部分仍然待检验，但「采纳率低」这条解释路径现在已经关闭：如果 `no_search` 真是 null，
**我不能再用「模型没用这个工具」来解释它**，因为它用了。

预测 C 的风险也解除了：畸形调用发生率 0.42，`no_recovery` 会真的触发。

### 我改了什么，没改什么

**改了成本估计。** 原估 $0.36 是错的，因为我按单条 $0.0025 算，而 max_steps=24 下
实测 **$0.0106**。主实验 144 条约 **$1.5**。数量级仍然可接受，如实更正。

**加了一个操纵检验（manipulation check），它不是一个条件。** 用完整提示
（`prompt_full`，没有删掉约束的那份）跑一遍 `full`，看正确率的天花板在哪。
理由：这批任务的正确率被「模型愿不愿意去仓库里找」压着，而那是前七轮的研究问题，
不是这一轮的问题。**如果不知道天花板，我就无法区分「部件没用」和「任务赢不了」。**

**没改任何预测、条件、指标或任务集。** 预测 A/B/C 的文字保持原样，包括已经证伪的那句。

### 试点暴露的两个限制，先记下来

1. **步数预算是绑紧的**：12 条里 8 条打满 24 步。这意味着正确率部分地在测
   「有没有在 24 步内做完」。我认为这是**合理**的——真实 agent 就是有预算的，
   浪费步数导致失败是一条正当的因果路径——但它意味着步数指标是**右删失**的，
   条件之间的步数差会被压缩，报告时必须说明。
2. **t10_moving_average 评分失败**（`invalid row`），12 个任务里丢 1 个。
   主实验里如果它持续失败，就是 11 个任务，如实报告而不是悄悄丢掉。

# 预注册：终止 bug 的两个修法，各值多少

写于修复代码之前。上半部分在看到结果后不改。

## 诊断（已完成，先摆事实）

第八轮顺带测出：**18 条正确轨迹里 12 条从不调用 `finish`**，写对代码后把预算烧到一步不剩。
144 条主实验数据里模式很清楚：

| | 每条命令数 | 命令失败率 | 正确率 |
|---|---|---|---|
| 打满预算（54 条） | **12.3** | **0.92** | 0.28 |
| 正常完成（85 条） | 5.8 | 0.80 | 0.47 |

轨迹尾部抓取（12 条独立探针，6 条打满预算）显示一个循环：
**写测试 → 跑 → 失败 → 重写测试 → 跑 → 失败**。`run` 占最后五个调用的 13/30。
其中一条把 `core.py` 写成 539 字节、跑失败、又写了一遍 539 字节——**逐字节相同**。

### 根因不在模型，在我的沙箱

真实脚手架里**每一条验证命令都失败**，没有一条是模型的错：

| 命令 | 结果 | 为什么 |
|---|---|---|
| `pytest -q` | 命令不存在 | 不在 PATH 上 |
| `python -m pytest` | No module named pytest | `python` 解析到 **msys2 的解释器**，不是跑 agent 的那个 |
| `python -m unittest discover` | NO TESTS RAN | 脚手架发的是 pytest 风格的 `def test_x()`，**unittest 发现不了函数式测试** |

**跑 agent 的解释器是 `Python3.12.1\python.exe`，agent 在 shell 里敲 `python` 得到的是
`D:/msys64/ucrt64/bin/python.exe`。** 我交给它的仓库**在构造上就是不可测的**。

这是我的沙箱的缺陷，不是模型的缺陷。

## 两个修法，分开测

**Fix A（环境）**：`Workspace.run` 把**当前解释器的目录**和它的 `Scripts` 放到 PATH 最前，
并把工作区根目录放进 `PYTHONPATH`。
离线验证过：修完 `pytest -q` 与 `python -m pytest -q` 都是 `3 passed`（修之前都失败）。
PYTHONPATH 是必须的第二半——控制台脚本 `pytest` 不把 cwd 放进 `sys.path`，
所以只修 PATH 的话裸 `pytest` 仍然 `ModuleNotFoundError`。

**Fix B（智能体）**：每轮告诉它**还剩几步**。它现在完全不知道存在预算这回事。

## 预测（预测 / 相反机制 / 各自行动）

### Fix A

**预测：完成率大幅上升**，从 0.44 升到 0.70 以上；命令失败率从 0.92 大幅下降。
**正确率也上升**，因为它终于能跑测试、能发现自己的错。
置信度：完成率 **0.80**，正确率 **0.50**。

**什么机制会产生相反结果。** 修好环境**不等于**修好智能体的命令选择。
如果它习惯敲的是 `python -m unittest discover`——那条即使环境正确**仍然返回
NO TESTS RAN**，因为脚手架的测试是函数式的——那么可用性提升了，它却用不上。
**这是真实风险：诊断里它确实反复敲 unittest。**

**行动。** 有大效应 → 采纳，并且**必须在第八轮补记一条重大限制**：
那 144 条是在一个无法验证的环境里跑出来的，所有效应都可能被压扁了。
null → 说明循环由命令选择驱动而非可用性驱动，那么下一步是在系统提示里
告诉它这个仓库怎么跑测试。

### Fix B

**预测：完成率中等上升，正确率不变或略降。** 置信度 **0.60**。

**什么机制会产生相反结果。** 模型可能直接无视数字；或者反过来**过早收工**——
看到「还剩 3 步」就草草 finish，正确率因此下降。**后者是真实的伤害风险，
所以正确率是这条的否决指标。**

**行动。** 完成率升且正确率不降 → 采纳。**正确率显著下降 → 撤销，不管完成率多好看。**

### 两者的交互

**我不预测交互方向。** A 修好环境后 B 的边际价值可能变小（不再卡住，自然会停），
也可能变大（能验证了，才知道自己何时算做完）。四格全跑，让数据说。

## 设计

`full_old`（都不开）/ `path_fix`（只 A）/ `budget`（只 B）/ `both`（A+B）
× 12 任务 × 3 次 = 144 条，约 **$0.7**。
指标同第八轮：正确率（差分执行）、完成率、模型调用数。
自助区间按**任务**重采样。

## 一条我先认下的话

如果 Fix A 有大效应，那么**第八轮那三个 null 的可信度要打折**——
在一个连测试都跑不起来的环境里，任何依赖「跑代码、读错误、改正」的部件
都发挥不出来。我会在 FINDINGS 里明确写下这一条，而不是让第八轮的结论就那么立着。

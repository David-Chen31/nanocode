# 预注册：终止 bug 的两个修法，各值多少

写于修复代码之前。上半部分在看到结果后不改。

## 诊断（已完成，先摆事实）

第八轮顺带测出：**18 条正确轨迹里 12 条从不调用 `finish`**，写对代码后把预算烧到一步不剩。
144 条主实验数据里模式很清楚：

| | 每条命令数 | 命令失败率 | 正确率 |
|---|---|---|---|
| 打满预算（54 条） | **12.3** | **0.92** | 0.28 |
| 正常完成（85 条） | 5.8 | 0.80 | 0.47 |

轨迹尾部抓取（12 条独立探针，6 条打满预算）显示一个循环：
**写测试 → 跑 → 失败 → 重写测试 → 跑 → 失败**。`run` 占最后五个调用的 13/30。
其中一条把 `core.py` 写成 539 字节、跑失败、又写了一遍 539 字节——**逐字节相同**。

### 根因不在模型，在我的沙箱

真实脚手架里**每一条验证命令都失败**，没有一条是模型的错：

| 命令 | 结果 | 为什么 |
|---|---|---|
| `pytest -q` | 命令不存在 | 不在 PATH 上 |
| `python -m pytest` | No module named pytest | `python` 解析到 **msys2 的解释器**，不是跑 agent 的那个 |
| `python -m unittest discover` | NO TESTS RAN | 脚手架发的是 pytest 风格的 `def test_x()`，**unittest 发现不了函数式测试** |

**跑 agent 的解释器是 `Python3.12.1\python.exe`，agent 在 shell 里敲 `python` 得到的是
`D:/msys64/ucrt64/bin/python.exe`。** 我交给它的仓库**在构造上就是不可测的**。

这是我的沙箱的缺陷，不是模型的缺陷。

## 两个修法，分开测

**Fix A（环境）**：`Workspace.run` 把**当前解释器的目录**和它的 `Scripts` 放到 PATH 最前，
并把工作区根目录放进 `PYTHONPATH`。
离线验证过：修完 `pytest -q` 与 `python -m pytest -q` 都是 `3 passed`（修之前都失败）。
PYTHONPATH 是必须的第二半——控制台脚本 `pytest` 不把 cwd 放进 `sys.path`，
所以只修 PATH 的话裸 `pytest` 仍然 `ModuleNotFoundError`。

**Fix B（智能体）**：每轮告诉它**还剩几步**。它现在完全不知道存在预算这回事。

## 预测（预测 / 相反机制 / 各自行动）

### Fix A

**预测：完成率大幅上升**，从 0.44 升到 0.70 以上；命令失败率从 0.92 大幅下降。
**正确率也上升**，因为它终于能跑测试、能发现自己的错。
置信度：完成率 **0.80**，正确率 **0.50**。

**什么机制会产生相反结果。** 修好环境**不等于**修好智能体的命令选择。
如果它习惯敲的是 `python -m unittest discover`——那条即使环境正确**仍然返回
NO TESTS RAN**，因为脚手架的测试是函数式的——那么可用性提升了，它却用不上。
**这是真实风险：诊断里它确实反复敲 unittest。**

**行动。** 有大效应 → 采纳，并且**必须在第八轮补记一条重大限制**：
那 144 条是在一个无法验证的环境里跑出来的，所有效应都可能被压扁了。
null → 说明循环由命令选择驱动而非可用性驱动，那么下一步是在系统提示里
告诉它这个仓库怎么跑测试。

### Fix B

**预测：完成率中等上升，正确率不变或略降。** 置信度 **0.60**。

**什么机制会产生相反结果。** 模型可能直接无视数字；或者反过来**过早收工**——
看到「还剩 3 步」就草草 finish，正确率因此下降。**后者是真实的伤害风险，
所以正确率是这条的否决指标。**

**行动。** 完成率升且正确率不降 → 采纳。**正确率显著下降 → 撤销，不管完成率多好看。**

### 两者的交互

**我不预测交互方向。** A 修好环境后 B 的边际价值可能变小（不再卡住，自然会停），
也可能变大（能验证了，才知道自己何时算做完）。四格全跑，让数据说。

## 设计

`full_old`（都不开）/ `path_fix`（只 A）/ `budget`（只 B）/ `both`（A+B）
× 12 任务 × 3 次 = 144 条，约 **$0.7**。
指标同第八轮：正确率（差分执行）、完成率、模型调用数。
自助区间按**任务**重采样。

## 一条我先认下的话

如果 Fix A 有大效应，那么**第八轮那三个 null 的可信度要打折**——
在一个连测试都跑不起来的环境里，任何依赖「跑代码、读错误、改正」的部件
都发挥不出来。我会在 FINDINGS 里明确写下这一条，而不是让第八轮的结论就那么立着。

# 运行之后

144 条（4 条件 × 12 任务 × 3 次，gpt-4o-mini，max_steps=24），**$0.78**。
原始数据 `results/termination.json`。基线 `old_env_no_budget` = 修复之前的真实代码。

## 结果

| 条件 | 正确 | 完成 | 打满预算 | 模型调用 | 命令数 | 命令失败率 |
|---|---|---|---|---|---|---|
| `old_env_no_budget` | 0.31 | 0.53 | 0.44 | 19.2 | 9.1 | 0.87 |
| `path_fix` | 0.31 | 0.61 | 0.36 | 15.7 | **4.6** | 0.77 |
| `budget` | 0.33 | 0.58 | 0.42 | 17.6 | 7.7 | 0.90 |
| **`both`** | **0.39** | **0.72** | **0.25** | **15.1** | **4.4** | 0.77 |

配对差（`both` − 基线，自助 5000 次，按任务重采样）：

| 指标 | 差 | 95% 区间 | 5000 次里修复更差的次数 |
|---|---|---|---|
| 正确率 | **+8.3** 点 | [+0.0, +22.2] | **0 / 5000** |
| 完成率 | **+19.4** 点 | [−0.0, +38.9] | 170 / 5000 = 3.4% |
| 模型调用 | **−4.2** 次 | [−6.7, −1.9] | — **区间不含 0** |

## 严格地说：只有一项显著

**模型调用减少 4.2 次（约 22%）是唯一区间不含 0 的结果。**

正确率和完成率的方向一致且不小，但**都压在边界上**：正确率的下界正好是 0.0，
完成率含 0。按我自己定的标准（95% 区间不含 0），**这两项不算显著**。

能诚实说的是：**5000 次重采样里，修复在正确率上一次都没有更差，在完成率上只有 3.4%
更差。** 这是方向性证据，不是显著性结论。n=12，区间就是这么宽。

## 逐条核对预测

**Fix A（环境）—— 未命中。** 我预测完成率单独就能升到 0.70 以上（置信度 0.80），
实测 **0.61**。环境修复单独不是主导因素。

**但我预测的机制是对的**：命令数从 9.1 **腰斩到 4.6**，命令失败率 0.87 → 0.77。
智能体不再空转了。**效应比我以为的小，但原因和我以为的一样。**

**Fix B（预算）—— 大体命中，否决未触发。** 完成率 0.53 → 0.58，
**正确率 0.31 → 0.33（没有下降）**。我事先把正确率定为否决指标，担心它为了指标提前收工——
**这个担心没有成真**。分级、只在末段警告、并要求说明「什么没做完」的设计似乎避免了它。
但 0.02 的变化在这个 n 下什么都证明不了，只能说**没有观察到伤害**。

**交互 —— 我说过不预测方向；点估计看似超可加，但正式交互没有证据。**

| | 完成率增量 | 正确率增量 |
|---|---|---|
| 只 A | +0.08 | +0.00 |
| 只 B | +0.05 | +0.02 |
| 单独之和 | +0.13 | +0.02 |
| **实测 A+B** | **+0.19** | **+0.08** |

事后的机制解释（**标注为事后**）：A 去掉了空转的**原因**（命令终于能跑），
B 去掉了空转的**持续性**（它知道该停了）。单独任一个都不够——
能跑测试但不知道何时收手，仍然会在别处绕；知道该收手但测试跑不起来，
只是更早地放弃。**打满预算的比例 0.44 → 0.25，几乎腰斩。**

事后补做差中差：正确率交互 +5.6 点 [−11.1, +22.2]，完成率交互
+5.6 点 [−27.8, +41.7]。区间都含 0，所以不能把「合并显著、单独不显著」
写成显著交互；上面的机制只保留为待验证解释。

## 兑现我预先认下的那句话

我写过：「如果 Fix A 有大效应，第八轮那三个 null 的可信度要打折。」

**Fix A 没有大效应。** 单独看，它对正确率的影响是 **+0.00**，对完成率 +0.08。
所以这个折扣**很小**，而不是我预想的那么大。

精确的说法是：第八轮确实跑在一个坏环境里，但那个坏环境**主要伤的是完成率和成本，
不是正确率**。所以第八轮「三个部件对正确率全部为 null」的结论**基本站得住**；
需要标注的是它的完成率与成本数字偏低。

**这比我承诺的折扣要小——但按数据该给多少就给多少，不因为事先许诺了大折扣就给大折扣。**

## 限制

- **n = 12 个任务**，两个主要指标都压在显著性边界上。需要更多任务或更多重复。
- 命令失败率修复后仍有 0.77。**我无法从这批数据区分**这是「智能体的测试真的失败了
  （有用的失败）」还是「它仍在敲跑不通的命令（无用的失败）」。这是下一步该测的。
- 交互的机制解释是**事后的**，没有预注册，需要独立验证。
- 单模型、单仓库规模。

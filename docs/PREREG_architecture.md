# 预注册：ReAct vs Plan-then-Execute

写于运行之前。上半部分在看到结果后不改。

## 为什么做这个

前九轮把上下文管理、搜索工具、错误处理、终止条件都测过了，其中一个（搜索工具）
被自己的数据否掉。但**整个项目最大的设计决定——循环结构本身——一个字的证据都没有**。
现在只能答「ReAct 是标准做法」，那是诉诸惯例，不是辩护。

## 任务集：真实仓库，隐藏验证

12 个脚手架任务是合成包里的单函数。**这个差距是实测出来的**：gpt-4o-mini 在脚手架上
0.42，在真实仓库任务上 0/4；而两个 agent bug（开场白被当成结论、不知道自己在哪）
**在脚手架上一个都不出现**。所以架构问题在真实代码上问。

仓库是 nanocode 自己，8 个任务，每个都是真会有人提的改动。

**验证测试对智能体隐藏**——跑完才写进工作区。如果它在运行时可见，智能体可以照着
断言逐条满足，那测的是阅读理解，不是改动是否有效。

评分要求**两个条件同时成立**：

    回归    仓库自带的 75 个测试仍然全过
    行为    隐藏的验证测试通过

任一单独都可以被钻空子：什么都不改能过回归，把 build 弄坏去满足验证不该得分。

**已验证**：8 个验证测试在未修改的仓库上**全部失败**（0 个 no-op），基线套件 75 passed。

## 公平性：这是这个实验的全部价值所在

**对照组做成稻草人，实验就一文不值，而且老师一眼看穿。** 所以：

- 相同工具、相同模型、相同温度、相同评分
- **相同总预算**。规划调用**占用 max_steps 的一步**，因为它真的花一次模型调用，
  不算的话等于白送这一臂一个回合
- **相同定位信息**。规划器同样能看到仓库结构，不是盲规划
- **计划是指导，不是脚本**。执行阶段允许偏离，提示里明说。
  强制盲执行一个「读任何文件之前写好的计划」才是稻草人——**没人那样用，赢了也不说明什么**

唯一的差别只有：ReAct 每一轮从当前状态决定下一步；plan-execute 先承诺一个序列，
再带着它行动。

这些公平性属性有离线测试钉住（`tests/test_plan_execute.py`），包括
「规划调用确实从预算里扣掉一步」和「计划确实进了执行者的系统提示」。

## 预测（预测 / 相反机制 / 各自行动）

**预测：正确率上 plan-execute 不会赢，甚至更差。** 置信度 **0.70**。

理由是信息顺序：**计划必须在读任何文件之前写**，而这些任务的难点恰恰在于
「代码现在长什么样」。读之前写的计划是猜测。

**什么机制会产生相反结果。** 这不是空话——我有具体证据支持相反方向：
第九轮测出打满预算的轨迹在**空转**（12.3 条命令、92% 失败），那是**缺少策略**的表现。
一个计划可能正好治这个。而且这 8 个任务里有 3 个要**同时改源码和 schema**
（r01、r02、r05），ReAct 很容易改完一处就去跑测试、忘掉另一处——
**计划天然防这种遗漏**。

**我另外预测**：plan-execute 的**模型调用数更少**（置信度 0.55），
因为它不需要边走边想。这条和正确率是两个独立的预测。

**行动。**
- ReAct 赢或打平 → 我对循环结构的选择第一次有了证据。答辩里的说法从
  「这是标准做法」变成「我实现了两种，测了，选了简单的那个」。
- **plan-execute 赢 → 我改默认架构。** 这一条我现在就写下来，
  免得事后用「样本小」把不想要的结果解释掉。

## 设计

2 臂 × 8 任务 × 3 次 = 48 条，claude-sonnet-5，max_steps=30，禁止提问。
预估 $10–20（单条 $0.15–0.4，失控时可到 $3+）。
自助区间**按任务重采样**——同任务的 3 次重复不独立。

## 一条我先认下的限制

仓库是 nanocode **自己**，是我写的代码。所以这证明不了「在别人的代码上也行」。
它证明的是「在一个真实的多文件仓库上，两种架构哪个好」。**这两句话不一样，
我不会把前者说成后者。**

## 任务难度校准（这部分是可用的）

ReAct 在 8 个任务上 **3/8 = 0.38**。**既没有触底也没有触顶，
说明这批任务留出了双向比较的空间**——如果两臂都是 0/8 或 8/8，
这个实验从一开始就没有功效。

而后者恰恰是我预测的机制，所以我更不能拿它当证据。

## 一个不在预测里的成本发现

我在设计里估的是单条 $0.15–0.4，实测 **$1.29–1.80**。差了一个数量级，
原因是我用 5 步就结束的 r08 做了成本冒烟测试，而真实任务要 20–31 步，
每一步都要重发整段历史。**又一次拿一条非典型轨迹当了典型轨迹**——
和第八轮 B 预测栽的是同一个跟头。

## 恢复运行：换了 relay，也换了模型

原账户额度耗尽。新 relay 只提供 4 个 gpt-5.x 模型，没有 mini 档，
且**不公开价目表**。两个后果，都记在这里：

**① 成本单位从美元改成 token。** 没有价目表时报美元等于把编的数字当测量值。
两臂跑同一个模型，token 是干净的比较单位，预算上限也改成按 token 计。

**② 模型换成 gpt-5.5**（可选项里不是最强的那个）。两条探针任务上它 **2/2**，
而 sonnet-5 在同样两条上是 1/2；且每条只用 **11 次模型调用 / 81.5k token**，
sonnet-5 是 25.5 次。**更便宜而且更强**，所以这不是为了省钱牺牲能力。

**sonnet-5 那 12 条不与新数据合并**，保存在 `results/architecture_sonnet_partial.json`。
换了模型又换了 relay，合并会把两个变量混进一个比较里。
